# 术语三段式：让所有读者随读随懂（R4 集中实现）

新人读文档最挫败的时刻，是读到一个缩写 / 黑话（LPN、SKU、幂等、灰度）不知道什么意思，又要停下来翻到词汇表、找完再翻回来接着读——节奏被打断很多次之后就放弃了。**这不是"词汇表章节做得够不够全"的问题，是词汇表和正文是不是断开的问题**，以及术语解释是否只服务技术人员的问题。

## 核心机制：术语三段式

Phase 1 提取术语时，**每个术语必须给出三段**：

1. **字面定义**：标准技术/业务释义（保留术语的标准用法，让读者能搜得到）
2. **通俗白话**：用产品/业务/测试/客服等非技术读者能直接理解的话解释（"幂等" → "同一个操作做一次和做一百次效果一样")
3. **业务场景绑定**：在当前项目具体业务里这个术语怎么体现、解决什么问题、出现于哪个流程环节

术语表是单文件 HTML 里的专门一章；正文里的术语自动挂 tooltip，hover 出三段式简注（不展开过长内容，需要细节点跳转词汇表章节）。

## 自动标注

在 Phase 5 组装单文件 HTML 时（`references/07-single-html-packaging.md`），生成正文 HTML 的同时做一遍术语标注：

1. Phase 1 术语提取产出的术语表是权威来源（`test-instance/extraction/glossary.json`）——每个术语一个唯一 ID + 三段式 + 所属域
2. 生成正文 HTML 时，扫描每一段文字，把命中术语表的词包一层 `<span class="term" data-term-id="xxx">`，鼠标悬停显示 tooltip
3. 不需要引入复杂的 NLP 匹配，字符串精确匹配就够——术语表本身已经是从代码里提取的确定性数据，不需要模糊匹配带来额外的误判风险
4. 点击术语（而不只是 hover）跳转到词汇表章节的完整条目

## 首次出现原则

同一个术语在文档不同章节都可能出现。读者很可能不是跳着读——大概率是按自己的关心点跳着读：

- 每个主要章节（不是整篇文档，是每个 `<section>`）里，术语**第一次出现**时除了 hover tooltip，还要在文字里带一个括号简注（"LPN（库位托盘编号 · WMS 用来定位库位的编码）"）
- 第二次及以后只留 hover，不重复括注，避免正文啰嗦
- 缩写类术语（全大写字母、驼峰缩写）优先级最高，一定要有首次括注；相对通俗的业务词（比如"退款"）不需要过度处理

## 跨域叫法的呈现

如果同一个概念在不同域叫法不同（术语表里带多个域的映射，见 `references/08-domain-segmentation.md`），tooltip 里要把其他域的叫法也展示出来，而不是只显示当前域的解释——这是直接解决"新人跨部门沟通鸡同鸭讲"的地方。术语表本身列出映射还不够，要让读者在读正文遇到这个词的当下就看到，不用专门跑去查表才知道"哦原来这个东西在物流域叫运单"。

## 枚举值映射

如果一个概念有枚举值（订单状态、审批状态、激活状态等），且**不同系统/不同域的枚举值不统一**，术语表里必须给出映射表。例：

| 业务概念 | 域 A 状态码 | 域 B 状态码 | UI 文案 | 说明 |
|---|---|---|---|---|
| 部署任务 | `pending` | 0 | 待执行 | 计划已生成但未开始 |
| 部署任务 | `running` | 1 | 部署中 | 至少一个 step 在执行 |
| 部署任务 | `success` | 2 | 部署成功 | 所有 step 成功 |
| 部署任务 | `partial` | 3 | 部分成功 | 部分 step 成功部分失败 |
| 部署任务 | `failed` | 4 | 部署失败 | 所有 step 失败 |

新人做跨域排查时能直接对照，省去"问一圈发现两边说的是一回事"的沟通成本。

- [ ] 每个术语都齐三段（字面 / 白话 / 场景）——缺一段的回到 Phase 1 补
- [ ] 正文里是否还存在肉眼可见的、词汇表里有条目但正文没标注上的术语（尤其检查缩写和跨域词）
- [ ] 跨域叫法差异是否在 tooltip 里直接展示（不是要读者去词汇表章节翻）
- [ ] 枚举值映射表是否覆盖了系统里所有有枚举值的状态字段
- [ ] tooltip 内容是否精简（一两句话 + 跳转），不要把整个词汇表条目的所有细节都塞进 hover 卡片
