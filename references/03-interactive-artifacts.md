# Phase 4：交互化呈现

静态图表/表格的问题：状态机有六七个状态十几个迁移事件时，静态迁移表太抽象；规则有数值边界时，读者看公式不如自己输个数字试试；库存多本账联动关系，静态表看不出联动效果。

这里设计的每个交互组件，最终都要作为一个独立的 JS 渲染函数 + 挂载点，嵌入 Phase 5 的单文件 HTML 里（不是各自单独生成一个 artifact 链接）。设计时就按"这段代码要能被塞进一个大 HTML 文件的某个 `<div>` 里"来写，避免用只能独立运行的 React 组件之类的形式，最后还要重新包一层。

## 状态机 → 可点击的状态图

- 节点 = 状态，边 = 迁移事件，来自 Phase 1 提取的状态迁移表（不要重新设计一套图，直接用提取到的数据驱动渲染）
- 点击一个状态节点，展开显示：可以从这个状态迁移到哪些状态、每个迁移的触发条件、涉及的副作用
- 用不同颜色/样式区分"正常路径"和"异常/补偿路径"，避免异常分支被视觉上淹没

## 业务规则 → 可输入的计算器

- 对有数值边界的规则（满减、分级、阈值），做一个输入框让读者输入具体数值（比如订单金额），实时高亮命中了哪条规则、走了哪个分支
- 规则的判断逻辑必须直接对应 Phase 1 提取的原始条件表达式，不要重新用自然语言实现一遍容易出偏差

## 多本账/联动数据 → 联动表格

- 库存这类"一个操作影响多张表/多个字段"的场景，用一个表格展示"操作 → 各账本字段的变化"，操作可切换（下拉选择不同的业务操作），表格随之更新对应哪些字段变了、怎么变的

## 词汇表高亮

- 如果生成的是长文档（Markdown），可以在正文里用 hover tooltip 的方式呈现黑话/缩写解释，减少读者跳转到词汇表的次数——这个可以做成一个轻量的 HTML 包装层，正文用 Markdown 渲染，术语用 `<span title="...">` 或类似机制标注
- 详情见 `references/09-glossary-tooltips.md`（R4 术语三段式）

## archify 图表的交互（不重复造轮子）

archify 图表的缩放/平移/适应/复位/节点聚焦**已由 `scripts/archify-inline.mjs` 提供的 `bundle.runtime` 实现**（R1 集中兑现路径的一部分），不要自己再写一套。每张图右上角自带工具栏（+ / − / 适应 / 复位），鼠标拖动平移、滚轮缩放、点节点高亮，键盘快捷键（`+` / `−` / `0` / `f`）。这套交互的视觉 token 与宿主一致，不引入第三方 UI 库，离线可用。

如果 Phase 4 还需要在 archify 图之外加**自定义交互组件**（状态机点击展开、规则计算器），按上面四节的范式写 IIFE 挂到宿主 window 即可，与 `bundle.runtime` 互不干扰。

## 何时不需要交互化

- 简单的实体字段列表、术语表本身 —— 用普通 Markdown 表格即可，不必为了炫技做成 artifact
- 判断标准：如果读者需要"改变一个输入去看不同结果"（数值、路径分支）才用交互；如果只是"查一个静态事实"就用表格
